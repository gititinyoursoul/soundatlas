# Grouping Route Events into Narrative Sections

## Goal

Organize a stable set of route events into a narrative structure that communicates the historical argument clearly.

The number of **narrative sections** does not need to equal the number of **route events**.

A route may contain six events but only four narrative sections if several events belong together conceptually.

## Core Principle

Route events and narrative sections serve different purposes.

**Route events** answer:

> What happened, where, and why does it matter?

**Narrative sections** answer:

> What part of the larger historical argument are we explaining here?

Several events may therefore belong to the same section when they demonstrate different aspects of the same historical development.

## Why Group Events

Grouping can prevent the route from falsely implying that every event happened in a simple causal sequence.

For example, three events occurring around the same time may represent:

* different communities
* different forms of agency
* parallel experimentation
* competing models
* simultaneous responses to the same historical conditions

Presenting them as three consecutive chapters may unintentionally suggest:

> Event A caused Event B, which caused Event C.

A shared section can instead communicate:

> These developments were happening alongside one another.

## Process

### 1. Keep the event cohort unchanged

Narrative grouping does not automatically remove route events.

If six events passed the minimum-sufficient cohort test, all six can remain active even if they are grouped into fewer sections.

For example:

* 6 route events
* 4 narrative sections

is completely valid.

### 2. Identify the function of each event

Use the cross-stop synthesis to determine what each event uniquely contributes.

Examples:

* foundation
* parallel innovation
* community agency
* infrastructure
* commercialization
* convergence

### 3. Look for events performing related historical work

Group events when they collectively answer the same larger narrative question.

For example:

**Section: Different communities reshape a cultural practice**

may contain:

* one event about ownership
* one event about dancers
* one event about technology

The events remain distinct, but the section explains why they belong together historically.

### 4. Avoid grouping based only on chronology

Events should not be grouped merely because they happened in the same year.

The grouping should have a conceptual reason.

Useful grouping relationships include:

* parallel development
* shared historical problem
* contrasting responses
* common transition
* convergence
* shared scale change

### 5. Use sections to express route shape

Narrative sections should make the route's larger structure visible.

For example:

**Section 1 — Emergence**

One event establishes a new model.

**Section 2 — Parallel experimentation**

Several events show different communities changing the culture simultaneously.

**Section 3 — Infrastructure**

One event shows the scene becoming connected or institutionalized.

**Section 4 — Convergence**

A later event brings several earlier mechanisms together.

The route still contains every individual stop.

### 6. Preserve event-level identity

Even when several events share a section, each should retain:

* its own title
* date
* location
* actors
* event text
* narrative role
* map position

Grouping should not blur historically distinct events into one generic chapter.

### 7. Decide whether the route should be event-centric or argument-centric

Two structures are possible.

## Event-Centric Structure

Each event becomes its own chapter.

Example:

* Chapter 1 → Event A
* Chapter 2 → Event B
* Chapter 3 → Event C
* Chapter 4 → Event D
* Chapter 5 → Event E
* Chapter 6 → Event F

This works well when:

* each event represents a clear chronological step
* the user experience centers on individual map stops
* transitions between events are strongly evidenced
* the route is primarily sequential

## Argument-Centric Structure

Several events may appear within one narrative section.

Example:

* Section 1 → Event A
* Section 2 → Events B, C, D
* Section 3 → Event E
* Section 4 → Event F

This works well when:

* several events represent parallel developments
* the route contains multiple communities or mechanisms
* chronology alone would imply false causation
* the larger historical argument matters more than one-stop-per-chapter symmetry

Neither structure is inherently better.

The structure should follow the evidence and intended user experience.

## 8. Check for accidental causal implications

After grouping, ask:

> Does the order imply relationships the evidence does not support?

If three parallel events are presented as separate sequential chapters, users may infer influence even if none is documented.

Grouping them under a shared section can make simultaneity explicit.

## 9. Keep route and narrative layers separate

A useful conceptual model is:

**Route layer**

* individual events
* locations
* map interactions
* evidence
* event metadata

**Narrative layer**

* sections
* themes
* transitions
* historical argument

The narrative layer organizes the route layer but does not replace it.

## Output

A completed narrative-grouping step should produce:

* final list of route events
* number of narrative sections
* assignment of each event to a section
* reason for each grouping
* section-level historical question
* section transition logic
* confirmation that no event was accidentally removed
* decision on whether the structure is event-centric or argument-centric

## Example

A route with six events might become:

**Section 1 — New model emerges**

* Event A

**Section 2 — Parallel developments**

* Event B
* Event C
* Event D

**Section 3 — System formation**

* Event E

**Section 4 — Later convergence**

* Event F

The route therefore has:

**6 events**

but:

**4 narrative sections**

This is not a reduction in historical content. It is a change in how that content is organized.

## Principle

The number of route events answers:

> **How many historical moments does the user encounter?**

The number of narrative sections answers:

> **How many major ideas are needed to explain the story?**

Those numbers should only be identical when the evidence and narrative structure genuinely support a one-event-per-section route.
