# Step 10b — Presentation and Visual Claims

## Purpose

Define how the route should communicate spatially and visually while
distinguishing current SoundAtlas capability from future product proposals.

## Required inputs

- `00-run-brief.md`
- `07-cross-event-synthesis.md`
- `09-evidence-audit.md`
- `10a-final-route-copy.md`
- Current map, timeline, StoryPanel, media, and data-model documentation and
  implementation evidence

## Work

Inspect the actual product before proposing treatment. Audit what chronology,
sequence, simultaneous visibility, marker emphasis, zoom, lines, clusters,
animation, imagery, and media would imply historically. Use only sourced
relationships. Treat media as unapproved leads until relevance, attribution,
rights, stability, and availability receive Human review.

## Output contract

Write `10b-presentation-visual-claims.md` with shared-schema presentation
records covering:

- current supported presentation using implemented capabilities;
- section/Event/relationship IDs, map states, and the claim each state
  communicates;
- parallel, sequential, network, contrast, and convergence treatment;
- prohibited or unsupported visual implications;
- media/artifact leads and unresolved approvals;
- accessibility and copy/presentation consistency requirements;
- future capability proposals clearly separated from baseline route needs; and
- product gaps routed to separate Intake work rather than implementation.

## Human boundary and stop condition

The Human accepts visual historical claims, media use, and presentation intent.
Do not implement a product capability or treat a proposal as current behavior.
